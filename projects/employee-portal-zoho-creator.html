The problem

This is a complete time, attendance and HR self-service portal built as a Zoho Creator application. It is meant for organizations that, for whatever reason, cannot use Zoho People or a dedicated timesheet product but do have access to Creator.

Common reasons an organization lands in this situation:

  • Zoho People or a third-party timesheet SaaS is not in the budget, but Creator already is, for example through Zoho One or an existing Creator plan.
  • The workforce mixes payroll staff, contractors and staff placed with client accounts, and off-the-shelf tools do not model that well.
  • Attendance rules, leave accrual and approval chains are specific to a country or a client contract and need custom logic.
  • The data has to live next to other Creator apps and sync with Zoho CRM and Zoho Desk.

The solution

A single portal that covers the whole employee lifecycle: clock in and out, breaks, leave, overtime, remote work approval, help desk tickets, feedback, scheduling, transfers and onboarding.

Daily jobs classify attendance, accrue leave and report on exceptions automatically. Every check-in, break and check-out is mirrored to Zoho CRM. Everything runs on the low-code platform: forms, reports, pages, Deluge scripts, schedules, approvals and a blueprint, plus custom HTML and CSS dashboards inside Creator pages.

Features

For employees
  • Clock in and out from a dashboard widget, with live status (working, on break, checked out).
  • Breaks and lunch (15 min, 30 min, 1 hour lunch), with automatic break-out when a shift is closed.
  • On-site vs remote detection: the check-in IP is compared to an office allow-list. Remote check-ins create a request a manager approves.
  • Late reasons prompted when arriving after shift start.
  • Overtime requests linked to a specific timesheet.
  • Leave requests (PTO, sick days) with day counting that skips weekends and holidays, and live balances.
  • Help desk tickets sent straight into Zoho Desk.
  • Feedback form, announcements and a company calendar.
  • Personal dashboard: hours this week, attendance score, days present and absent, days since hire, shift schedule.
For managers & admins
  • Admin dashboard with attendance status counts across the company.
  • Approval workflows for leave, remote attendance and overtime, with templated emails.
  • Shift management: define shifts once, assign them, and scheduled hours are calculated automatically.
  • Employee transfers between client accounts, shifts and managers, with an audit record.
  • Onboarding blueprint that holds new records until hire date and shift data are complete.
  • Workday calendar with holidays and company days off.
  • Per-account and per-region reports: a client sees only the staff placed with them, split by country.
  • Portal invitations in one click.
Automation
  • Daily attendance status: after each shift end, classifies the day as Present, Undertime, Absent, No Check-Out or On Leave.
  • Daily leave accrual: PTO and sick-day balances, idempotent per date.
  • No time-in report: emails admins who never clocked in.
  • Weekly attendance report: an HTML summary table of each employee's week.
  • Workversary reminder to the HR team.
  • Stale shift expiry: closes shifts left open past scheduled end plus a grace period.

Integrations

  • Zoho CRM: every check-in, break and check-out is mirrored to a CRM Attendances module, linked to a Contact (management) or Candidate (staff) record.
  • Zoho Desk: tickets created in the portal are pushed to Desk and their status is read back.
  • Zoho Catalyst: the "Submit a Ticket" page embeds a Catalyst-hosted form, prefilled with the signed-in employee's name and email.
  • Custom JS widget API: the Widget* Deluge functions back a JavaScript time-clock widget embedded in the dashboard.
  • IP geolocation lookup for remote check-ins.

Technical highlights

01

Deluge at scale

About 1,800 lines of server-side Deluge across 47 functions, organized into namespaces: PTO, calendar, shift, tickets, tools.

02

A small JSON-style API inside Creator

The Widget* functions return maps with a crash-safe default status ("error"), so a custom JavaScript widget can drive the whole time clock.

see the pattern →
03

One source of truth for the calendar

calendar.getDayClassification decides whether a date is a workday, weekend, holiday, company day off or approved leave for an employee. Accrual, absence marking and reports all reuse it.

04

Result maps instead of exceptions

PTO.applyLeaveUsage validates the employee, applies policy rounding, checks the balance for the leave type and returns {success, message} so the workflow can show a clear message.

05

Idempotent schedules

The leave accrual job records the last processed date (Last_Accrual_Date), so a re-run never double counts.

06

Guarded state changes

WidgetGoOnBreak rejects invalid break types and double breaks, writes a subform row and returns server timestamps so the browser timer stays in sync.

see the pattern →
07

Self-healing data

WidgetExpireStaleShifts closes shifts still open 2 hours past scheduled end (or from a previous day), ends open breaks and marks the timesheet "No Check-Out" so reports and payroll stay accurate.

08

On-site vs remote branching

WidgetCheckIn blocks double check-ins, geolocates the IP, compares it to the allow-list, then either creates the timesheet or opens a prefilled Remote Attendance form for approval.

09

Logging that can't break the caller

tools.logInfo / logWarn / logError write level, source, status, message, user and record ID to an App_Logs form. Logging failures are swallowed on purpose.

see the code →
10

Custom UI inside Creator pages

Dashboards are hand-written HTML and CSS rendered through ZML, with design tokens as CSS variables, instead of the default page builder widgets.

11

Role-based access

Separate permission profiles for Administrator, Manager, Team Supervisor, Employee, Client and Read-only users.

12

Localized HR fields

The employee record supports country-specific data such as civil status, nationality, residence type, dependents and local bank accounts.

Daily jobs

  • Stale shift expiry (WidgetExpireStaleShifts): any timesheet still open 2 hours past its scheduled end, or from a previous day, is closed as No Check-Out and its open breaks are ended.
  • Attendance status (dailyAttendanceStatusUpdate): runs per employee after their shift end. Uses calendar.getDayClassification to skip weekends, holidays, company days off and approved leave, then sets the day to Present, Undertime or Absent.
  • Leave accrual (PTO.dailyLeaveAccrual): adds the per-day PTO and sick-day rate for the employee's location. Guarded by Last_Accrual_Date so it runs at most once per day.

Code samples

Representative Deluge excerpts. The full app is not published; these show how the code is written.

// Structured in-app logging. Writes level, source, status, message and
// user to an App_Logs form, giving admins an audit trail inside Creator.
// Logging failures are swallowed so they can never break the caller.

void tools.appLog(string level, string source, string status, string message, string recordId)
{
	try
	{
		insert into App_Logs
		[
			Level=level
			Source=source
			Status=status
			Message=message
			User_Email=zoho.loginuserid
			Record_Id=recordId
			Logged_At=zoho.currenttime
			Added_User=zoho.loginuser
		]
	}	catch (e)
	{
		// swallow errors: logging must never break the caller
	}
}

tools.appLog · structured in-app logging that can never break the caller.

void tools.logInfo(string source, string status, string message)
{
	thisapp.tools.appLog("INFO",source,status,message,"");
}

void tools.logError(string source, string message)
{
	thisapp.tools.appLog("ERROR",source,"error",message,"");
}

logInfo / logError · thin wrappers so every call site logs in one line.
